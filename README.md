# Бизнес-задача

Разработать платформу для продажи, управления и автоматического обслуживания VPN-подписок, поддерживающую несколько VPN-панелей (Remnawave, 3x-ui и другие), различные модели тарификации, динамический подбор серверов и расширяемую систему дополнительных возможностей.

## Основная цель

Предоставить пользователю возможность приобрести VPN-подписку, которая может состоять как из заранее подготовленного тарифа, так и быть полностью сконфигурирована через конструктор.

Система должна автоматически:

* рассчитывать стоимость подписки или заготовленый план с указанной ценой и тарифом;
* создавать VPN-аккаунты в соответствующих панелях;
* выбирать оптимальный сервер;
* контролировать срок действия и лимиты;
* продлевать подписки;
* управлять трафиком и устройствами;
* поддерживать различные протоколы и дополнительные функции.

## Типы подписок

Система должна поддерживать различные модели ограничений:

### Временные подписки

Примеры:

* 30 дней;
* 90 дней;
* 365 дней.

### Трафиковые подписки

Примеры:

* 100 ГБ;
* 500 ГБ;
* 1 ТБ.

### Комбинированные подписки

Примеры:

* 30 дней + 100 ГБ;
* 90 дней + безлимитный трафик;
* 365 дней + 1 ТБ.

### Подписки без срока действия

Примеры:

* 500 ГБ без ограничения по времени;
* 1 ТБ Lifetime.

## Ограничения

Подписка может содержать:

* ограничение по времени;
* ограничение по объему трафика;
* ограничение по количеству устройств;
* ограничение по количеству одновременных подключений;
* ограничение по регионам;
* ограничение по протоколам.

## Стратегии учета трафика

Система должна поддерживать различные стратегии использования трафика:

* без сброса;
* ежемесячный сброс;
* еженедельный сброс;
* сброс каждые N дней;
* пользовательские стратегии.

## Продление подписок

Подписки должны поддерживать различные механики продления:

* увеличение срока действия;
* увеличение лимита трафика;
* продление и увеличение трафика одновременно;
* замена текущего тарифа новым;
* переход между тарифами.

## Конструктор тарифов

Пользователь должен иметь возможность самостоятельно выбрать:

* срок действия;
* объем трафика;
* количество устройств;
* протоколы;
* дополнительные функции;
* стратегию сброса трафика.

Стоимость должна рассчитываться автоматически.

## Дополнительные возможности

Подписка может содержать дополнительные функции:

* White List;
* Dedicated IP;
* GEO Routing;
* XRay Routing;
* Anti DPI;
* Gaming Mode;
* Priority Traffic;
* другие функции в будущем.

Каждая функция может влиять на стоимость и требования к серверу.

## Поддерживаемые протоколы

Система должна поддерживать один или несколько протоколов одновременно:

* VLESS;
* VMESS;
* Trojan;
* Shadowsocks;
* WireGuard;
* Hysteria2;
* TUIC;
* будущие протоколы без изменения бизнес-логики.

## Управление VPN-инфраструктурой

Платформа должна работать с несколькими VPN-панелями одновременно.

Каждая панель представляет отдельный провайдер инфраструктуры.

Примеры:

* Remnawave #1;
* Remnawave #2;
* 3x-ui #1;
* 3x-ui #2;
* 3x-ui #3.

Для каждой панели должны храниться:

* адрес подключения;
* учетные данные;
* поддерживаемые возможности;
* список серверов.

## Управление серверами

Каждый сервер имеет:

* местоположение;
* текущую нагрузку;
* поддерживаемые протоколы;
* поддерживаемые функции;
* ограничения по вместимости;
* статус доступности.

## Автоматический выбор сервера

При создании подписки система должна автоматически подобрать сервер на основании:

* поддерживаемых протоколов;
* требуемых функций;
* доступности;
* совместимости возможностей;
* текущей нагрузки;
* бизнес-правил балансировки.

## Биллинг

Система должна обеспечивать:

* создание заказов;
* расчет стоимости;
* применение скидок; (В будущем)
* промокоды; (В будущем)
* партнерскую программу; (В будущем)
* прием платежей;
* возвраты средств;
* историю операций.

## Автоматизация

Система должна автоматически:

* активировать подписки после оплаты;
* создавать VPN-пользователей;
* продлевать подписки;
* отключать просроченные подписки;
* контролировать лимиты;
* выполнять сброс трафика по расписанию;
* переносить пользователей между серверами при необходимости.

## Масштабируемость

Архитектура должна позволять без изменения доменной модели добавлять:

* новые VPN-панели;
* новые протоколы;
* новые типы ограничений;
* новые стратегии тарификации;
* новые функции;
* новые платежные системы;
* новые алгоритмы балансировки серверов.
